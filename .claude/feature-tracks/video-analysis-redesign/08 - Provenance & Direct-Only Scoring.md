# 08 - Provenance & Direct-Only Scoring

**Phase:** Analysis Core
**Status:** not-started
**Estimated effort:** 2 sessions

## Overview

**Objective:** geometry provenance threads from pose post-processing through metrics into
scoring (plan D4, WP-016/017/033), and the audit's live correctness bug dies: interpolated
keypoints are currently scored as measured.

**Current state:** per-keypoint `st` codes (MISSING/PROVISIONAL/OK/INTERP) exist in the
artifact — and nothing reads them. Interpolated points get hardcoded conf 0.45 >
`metrics.MIN_CONF` 0.35, so they pass the measurement gate; `scoring.py` consumes only
checkpoints/summary/glossary/tempo. Scoring config has conf/view/club gates + abstention but
no provenance concept.

**Target state:** the plan vocabulary (`model/tracked/propagated/derived/manual_correction/
missing`) mapped additively onto `st`; metrics compute per-value provenance + confidence
dependencies; scoring config (versioned v3) declares `accepted_provenance` /
`direct_only` / min-confidence per check; a `direct_only` check whose event frame lacks a
direct observation triggers forced inference (planner hook from step 07) or abstains with a
structured reason. Propagated/interpolated geometry can never silently satisfy a scoring
dependency — gate: **propagated-represented-as-direct = 0**.

## Steps

1. Map `st` → plan vocabulary in the artifact (additive `prov` alongside `st`; manual
   corrections remain DB-side and map to `manual_correction` at merge time — document that
   clients own that mapping).
2. `metrics._p` gains a provenance-aware mode: measurement path requires OK/PROVISIONAL-
   with-conf (i.e. excludes INTERP/PROPAGATED) unless a check explicitly accepts derived;
   drawing/series path unchanged (display keeps dense geometry).
3. Scoring config v3: per-check `geometry: {frame: event, direct_only, accepted_provenance,
   min_keypoint_confidence, min_event_confidence, on_failure: abstain}`. Defaults chosen so
   v3 == v2 semantics EXCEPT interpolated evidence no longer counts — every other delta is a
   deliberate edit.
4. Forced-frame loop: after events finalize, checks marked direct_only whose frame lacks
   direct geometry request inference via the planner's forced set (07 already forces all
   event/checkpoint frames, so this is the assertion + the escape hatch for future sparse
   policies).
5. `validate_scoring_config.py` extended: every v3 field resolves AND the provenance gate is
   exercised by at least one fixture (the standing trap: existence ≠ meaning — print raw
   values across all fixtures for any check whose band moved).
6. Rescore all fixtures with v3; review every score delta; goldens re-frozen deliberately.
